# Adversarial review of penult v1

*2026-11-06, branch `v1` at 4802e40. Read-only review: design.md, .claude/CLAUDE.md, README, every module, the skill, the tests, pyproject. `pytest -q`: 6 passed. `ruff check .`: clean, but the config selects only D100; `ruff --select F,B,UP,SIM` finds 6 (F541 tools.py:251, UP031 tools.py:161, ...). `python -m penult --help`: 13 verbs. Findings were reproduced against real git, real ductus/penlike output, and article's CLI where marked "verified".*

Format: severity, file:line, the problem, then the fix in one line.

## Blockers

- **blocker** penult/tools.py:383 + penult/images.py:155 + penult/data/skills/penult/SKILL.md:58: the skill says "commit and push the workspace" (thorwhalen/essays is PUBLIC), and two files in it hold private data. `check.md` carries penlike's figures from the author's private model ("the author's usual 0.38 (spread 0.33, over 8 texts)"), and a penlike failure there lists every private model name (verified). `penult.json` `images[].origin` stores the absolute local path of every `image-add` source, e.g. `/Users/<name>/Downloads/x.png` (verified). Fix: write check.md and the penlike half of `last_check` under the data root (or a gitignored `.penult/` that `start` gitignores), and store `origin` only when it is a URL.
- **blocker** penult/github.py:152: `names` are `str(Path.relative_to(...))`, so they have backslashes on Windows, while git prints `/`. Nothing ever matches, so the push check always passes on Windows. `test_the_one_command_path` expects a refusal there and will fail on the Windows CI job (`test_on_windows = true`), which blocks the release. Fix: use `.as_posix()` (and `-z` parsing, see below).

## Major

- **major** penult/tools.py:243: ductus segments have no `text` key; the text is at `span.quote` (verified against `ductus gauge --format json`, schema keys `span/signals/lean/strength/label`). Every flagged line in check.md reads `""` (verified). `direction == "machine"` and `note` are right. Fix: `(seg.get("span") or {}).get("quote")`.
- **major** penult/render.py:70-73: `"\n".join(["# T", "", "*S*", ""]) + body` leaves a single newline after the subtitle, so `*S*` fuses into the first paragraph of every posted draft (verified: `'# T\n\n*S*\nFirst para.'`). The module doctest only passes because `NORMALIZE_WHITESPACE` hides the missing blank line. Fix: `"\n".join(head) + "\n" + body.strip()`, and assert `"*S*\n\nFirst"` in the smoke test.
- **major** penult/tools.py:401-412: the approval is never invalidated. After `approve`, an edited essay.md, a re-`post`, or `start --force` (stage back to `seeded`) all leave `approved` set, so `publish` sends text the author never saw (verified). Fix: store the sha256 of essay.md and the comment version in `approved`; `publish` refuses on a mismatch, and `post`/`start --force` clear it.
- **major** penult/tools.py:115: `start --force` ("refetch the seed") also overwrites brief.md, which destroys the filled-in thesis, assumptions, and the author's answers to the thin-seed questions. It also resets `stage` to `seeded` (tools.py:122). Fix: never rewrite brief.md once it exists (offer `--rewrite-brief`), and keep the stage.
- **major** pyproject.toml:23-27: `publish` needs `article[substack]` (python-substack, markdown-it), but the core depends on bare `article` and no penult extra pulls it in. After `pip install penult`, `penult publish` fails inside article. Fix: add the extra `publish = ["article[substack]"]` (or depend on `article[substack]`) and name it in the error at tools.py:438.
- **major** penult/tools.py:188, 437: ductus, penlike and article are found with `shutil.which`. Under `pipx`/`uv tool install 'penult[style]'` or an unactivated venv, their scripts are not on PATH, so check reports "not installed" and publish refuses even though the packages are installed. Fix: run `[sys.executable, "-m", "<pkg>"]` when `importlib.util.find_spec(pkg)` finds them, and fall back to PATH.
- **major** penult/github.py:142: raw URLs pin the *current branch*. In the owner's own flow (branch, squash-merge, delete the branch) every image in the posted review comment 404s after landing. On a private essays repo raw URLs never render in comments at all. Fix: pin the commit SHA (`git rev-parse HEAD`) in the raw URL; when the repo is private, warn or use `github.com/<o>/<r>/blob/<sha>/<path>?raw=true`.
- **major** penult/github.py:155-163: porcelain/log output is parsed by `line[3:].strip('"')`. Non-ASCII names come back octal-escaped (`"docs/ess/img/caf\303\251.png"`) and staged renames as `old -> new`, so those images count as pushed and `post` goes ahead with broken pictures (verified with café.png, both untracked and committed-but-unpushed). Fix: `git status --porcelain=v1 -z` and `git log -z --name-only`, then split on NUL.
- **major** penult/tools.py:383: `[p for p in images if p.is_file()]` drops images that do not exist from the push check, so `post` posts a comment with 404 images that `render` reported as missing. `post` also never checks that comment.md is newer than essay.md, so a stale render gets posted. Fix: refuse when any referenced image is missing, and record the essay hash at render and compare it in `post`.
- **major** penult/tools.py:455-457: the draft link is scraped from human text (`Edit the draft:` plus `\S+`), which picks up a trailing `.` or `);` (verified), and a Medium run sets `draft_url=None`. That erases the Substack draft link, so the next Substack publish runs without `--update` and makes a duplicate draft. Fix: call `article draft-substack --json-out`, read `results[0].detail.edit_url`, and keep `drafts[platform]` in state.
- **major** penult/images.py:143: `urllib.request.urlopen` sends the default `Python-urllib` user agent, which Wikimedia rejects with 403 (verified on upload.wikimedia.org). Many Openverse hits are Wikimedia, so `image-search` followed by `image-add <url>` fails on the main path. Fix: send a descriptive User-Agent (or use illustration's own downloader).
- **major** penult/store.py:151-158: `prefs-set` does not check types. `penult prefs-set voice_models me` stores the string `"me"` (verified), and then `check` runs penlike for models `m` and `e` while the brief says `m, e`. `max_generated_images two` raises a raw `ValueError` in `image-generate`. Fix: coerce or validate against `type(DEFAULT_PREFERENCES[key])` (a str goes to `[str]` for list keys) and raise PenultError otherwise.
- **major** misc/docs/design.md:25,42 + penult/tools.py:78-125: seam 2 is partly fake. The replacement it names (hubcap, REST) cannot plug into `runner=`, which is subprocess-argv shaped, without faking `gh` argv; `post_comment`/`edit_comment` are called directly. The "second seed type" is not additive either. `start` takes `issue_url` and requires `owner`/`repo`/`number`/`url` (tools.py:102,121), `post` needs an issue URL (`parse_issue_url`), and a Discussion needs GraphQL `addDiscussionComment`. "start already takes the fetched dict" is false. Fix before the first release: a declared `Seed` TypedDict (with `review_target` optional), a `reviewer=` seam (post/edit callable) next to `fetch=`, and the positional renamed to `seed` now, while renaming is free.
- **major** penult/tools.py:439-450: seam 5 has no injection point. Platforms are an `if/elif` on hardcoded argv, so the replacement the table points at (article's dev.to and hashnode adapters) means editing `publish`. Fix: a `{platform: argv_builder}` registry or a `publisher=` callable.
- **major** penult/data/skills/penult/SKILL.md:3,11,85 + README.md:9: "Never publishes publicly / nothing you do publishes anything", yet the whole essay is posted as a comment on a public issue before its Substack publication: indexed, and a duplicate-content source for the later canonical URL. Fix: say so plainly in the skill and README, and add a `review_repo` preference (a private repo) or warn in `post` when the repo is public.

## Minor

- **minor** penult/images.py:53: illustration's `ImageResult` names the landing page `source_page_url`, which is not among the names tried, so `page` is always None and CC-BY credits lose their source link. Fix: add `source_page_url` (and `author_url`, `license_url`).
- **minor** penult/render.py:30: the image regex misses single-quoted and parenthesised titles, `<angle bracket paths>`, paths with spaces, escaped quotes in captions, nested brackets in alt text, and reference-style `![a][ref]` images. These are neither rewritten nor checked by `post`, so they become broken relative links in the comment (verified). Fix: parse with markdown-it (already in article[substack]) instead of a regex.
- **minor** penult/render.py:65: `src.lstrip("./")` strips characters, not a prefix: `../shared/x.png` becomes `shared/x.png` and `/docs/x.png` becomes `docs/x.png`. `quote()` turns `%20` into `%2520`. Fix: `posixpath.normpath(posixpath.join(rel_folder, unquote(src)))` against the repo root.
- **minor** penult/render.py:67-69: the caption is inserted inside a linked image (`[![a](u)\n\n*Cap*](link)` breaks the link), images inside code fences are rewritten, and a `*` in a caption breaks the italics (verified). Fix: skip fenced code, keep a linked image's caption outside the link, and escape `*`/`_`.
- **minor** penult/render.py:51-54: `ArticleValidationError` (an essay with no title) is not a PenultError, so the CLI prints a traceback (verified). Fix: catch `article.base.ArticleError` in `_fields` and re-raise it as PenultError.
- **minor** penult/tools.py:348,356: `folder_url` is computed and then `del`eted: dead code. Fix: delete both lines.
- **minor** penult/github.py:35: `_REMOTE` rejects repos with dots (`o/my.repo.git`, `*.github.io`) and ssh host aliases (`github-work:`), and tools.py:102 compares owner/repo case-sensitively, so `start` refuses from a valid checkout. Fix: `([^/]+?)(?:\.git)?/?$` and `.lower()` on both sides.
- **minor** penult/github.py:34: `_ISSUE_URL` is unanchored (it accepts `notgithub.com/...`). Fix: `^https?://(www\.)?github\.com/`.
- **minor** penult/data/skills/penult/SKILL.md:30-54: `penult mark --stage drafted`, `image-search`, `image-add` and `image-generate` are shown without a workspace, so they fail unless the agent's cwd is the workspace (start is run from the repo root). Fix: write `<workspace>` / `--folder <workspace>` in every example.
- **minor** penult/__main__.py:58 (via cw): short flags collide: `-f` is `--force` (start) and `--folder` (image-search, image-add); `-n` is `--n`, `--name`, `--new` and `--note`. The image verbs take `--folder` while every other verb takes a positional folder. Fix: one positional `folder` everywhere, `n` renamed `count`, and no short flags for `force`/`new`.
- **minor** README.md:65: `gh skill install` is not a command in the local gh (2.72: unknown command "skill"). Fix: verify the gh version it needs, or document the copy or symlink install.
- **minor** penult/store.py:63-64: penult invents article's file locations (`~/.config/article/.env`, `~/.local/share/article/pipeline_state.json`), while article's own defaults are `.env` and `pipeline_state.json` in the cwd: two SSOTs, and drafts made with `article` directly are not seen for `--update`. Fix: pass `-e`/`-s` only when the preference is set (default `None`).
- **minor** penult/tools.py:225: ductus is given the raw file, so the front matter and the image syntax are gauged as prose (segment 0 is the front matter). Fix: feed `markdown_to_fields(...)["content_markdown"]` on stdin (`ductus gauge -`).
- **minor** penult/tools.py:259: penlike's lines already start with `- `, so check.md shows `- - colons per 100 words`. Fix: strip a leading `- ` before re-bulleting.
- **minor** penult/tools.py:190: the injected runner is called with no timeout, and `_tool_json` checks `shutil.which` before the runner, so `check` cannot be tested with fakes; it has no test. Fix: probe through the runner and add a fake-JSON test for both tools.
- **minor** penult/workspace.py:88-91: `is_thin` looks for a thesis in the body only (not the title or comments) and counts any `x. ` (`e.g. `, a URL followed by a space) as one. It counts pasted logs or code as words, and after `start --force` it counts penult's own posted drafts, so a refetched seed is never thin. A `None` body raises TypeError. Fix: drop comments by the penult-posted `comment_url` author/id, and strip code and URLs before counting.
- **minor** penult/workspace.py:186-206: on refetch, seed.md ("the point of departure, kept as it was") absorbs penult's own draft comments. Fix: exclude the comment(s) recorded in state, or never rewrite seed.md (write `seed-<date>.md`).
- **minor** penult/tools.py:113: `start` writes seed.md and brief.md into an existing `docs/<slug>/` that is not a penult workspace (no refusal); the essays repo already has a `docs/`. Fix: refuse when the folder exists and is non-empty without penult.json.
- **minor** penult/images.py:139-140: the suffix comes from the URL path (`.png` when it has none, whatever the bytes are), and an existing `img/<name>` is silently overwritten. Fix: sniff the content type, and refuse to overwrite without `force`.
- **minor** penult/images.py:188-192: a generator that is billed and then fails (`image.save` raising) leaves no ledger row, so the spend is not counted against the budget. Fix: record a `generated-failed` row in a `finally`, counted toward the budget.
- **minor** penult/tools.py:435-448: `publish --platform medium --dry-run` skips the approval gate and runs the real `syndicate-secondary` (harmless today, since article's Medium step sends nothing). The README and skill promise an "unpublished Medium draft" where article only prints Import-a-story steps. Fix: refuse `--dry-run` for medium, and reword the claim.
- **minor** penult/tools.py:380-381: outside a GitHub checkout, `post` skips the push check silently. Detached HEAD gives `branch == "HEAD"` raw URLs. Fix: refuse (or warn) in both cases unless `--raw-base` was given.
- **minor** penult/tools.py:401: `approve --by` defaults to "the user", so the gate records no one. Fix: make `by` required.
- **minor** pyproject.toml:81-84: ruff selects only D100, so "All checks passed" says nothing. Fix: `select = ["D100", "F", "B", "UP", "SIM"]`.
- **minor** tests/test_smoke.py:194: the import check omits `pydantic`, `article` and `dol`. None of them load today (verified: `import penult` pulls none of cw/illustration/aix/ductus/penlike/pydantic/article/dol; `penult.__main__` adds only cw), but nothing keeps it that way. Fix: add them to the tuple.
