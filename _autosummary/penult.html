penult#

penult: from an idea to a publication draft, posted where its author can review it.

The seed is a GitHub issue. penult fetches it into a workspace next to it, holds the brief, the research notes, the essay, the images and their credits, checks the draft with ductus and penlike, renders it as an issue comment, and, once the author says so, hands it to article for an unpublished Substack or Medium draft. The thinking in between (research, drafting, the style passes) is an agent’s, laid out in the penult skill; the verbs here keep every step from being improvised twice.

penult.approve(folder=None, *, by='the user', note='')[source]#

Record that the person is happy with the posted draft, as it stands now; this lets publish run.

Only set it when the person said so, in their words; quote them in --note. The approval is of this text: if essay.md changes afterwards, publish refuses until the person approves again.

Return type:

penult.check(folder=None, *, like=None, style=None, out=None, data_dir=None, files=None, runner=<function run>)[source]#

Read the essay with ductus and penlike, and write what they found to a private check file.

ductus marks the segments that read machine-made (lean toward +1, with the evidence strength); penlike measures the draft against each voice model in like (the voice_models preference by default). The report quotes figures from the author’s private style models, so it goes under the data root (work/<slug>/check.md), not into the workspace, unless out says where. The agent’s own reading comes on top of this; neither tool sees bland prose that carries no tell.

penult.layout(folder=None, *, apply=False)[source]#

Each image’s size class against the layout rules; --apply writes the suggestions.

The rules (penult.figures, from the layout research in misc/docs/research/): the hero is landscape at column width or an inset; a square or portrait body image is an inset; a landscape one, a diagram or a chart takes the column; after the hero, about one image per 500 words at most. The class goes in essay.md’s images: front matter, which render honours as <img width> and publish as python-substack’s image marker. --apply sets every unset image’s class to the suggestion (a class set by hand is kept; to change one, edit the front matter).

penult.publish(folder=None, *, platform=None, dry_run=False, data_dir=None, files=None, runner=<function run>, publisher=None)[source]#

Hand the approved essay to the publisher for an unpublished draft on the platform.

The default publisher is the article package (Substack draft, or Medium’s import step); the draft’s editor link comes back and the person publishes by hand. Refuses before penult approve, and after any change to essay.md since the approval, unless --dry-run (which converts and checks, sending nothing).

penult.render(folder=None, *, raw_base=None, data_dir=None, files=None, runner=<function run>)[source]#

Write comment.md: the essay as a GitHub comment, relative images turned into raw URLs.

raw_base is worked out from the checkout (owner, repo, commit, folder) when not given; pinning the commit keeps the links alive after the branch is merged. The comment ends with a footer naming the seed and the research folder.

Return type:

penult.start(seed, *, into=None, force=False, data_dir=None, files=None, fetch=None, runner=<function run>)[source]#

Fetch the seed (a GitHub issue URL) and make the workspace: seed, brief, state.

The workspace goes into the folder given, else to the workspace preference (docs/<slug> by default) inside the checkout of the issue’s own repository that holds the current directory. A thin seed (few words, no thesis) is reported so the agent asks the user before researching. --force refetches the seed into an existing workspace; the brief and the stage are kept.
