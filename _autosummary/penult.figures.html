penult.figures#

Illustration layout: how big each image is drawn, and where, on every renderer.

The rules come from misc/docs/research/2026-11-06-illustration-layout-for-essays.md (sourced where it could be, judgment where it says so). The short version:

  • An image has a size class: inset (about half the column, centred), normal (the column, the default), large (wider than the column; Substack renders it on the web only) or full (edge to edge; opt-in, for an image that is the content). The vocabulary mirrors what Substack, Medium and the Guardian’s renderer already have.

  • The hero (the first image, under the title) is landscape at column width, or an inset. A square or portrait image at column width is drawn taller than a laptop screen, which is the complaint this module exists to answer.

  • A body image that is square or portrait is an inset; a landscape one, a diagram or a chart is normal. Few images: after the hero, at most one per 500-1000 words.

  • Captions are one line, not italic (the platforms draw them small, centred, upright).

The class lives in the essay’s front matter, out of the Markdown that goes to the publisher:

images:
  img/hero.png: inset

A GitHub comment honours it as <img width>; python-substack honours it through its own <!-- python-substack-image:v1 ... --> marker, which substack_markdown() writes after each sized image. Neither {width=...} nor <img> may go to python-substack (the first turns the image into its alt text, the second drops it).

>>> sizes_from_fields({"images": {"img/a.png": "inset"}})
{'img/a.png': 'inset'}
>>> suggest_size(1024, 1024, hero=True)
('inset', 'square hero: at column width it is taller than a laptop screen')
>>> suggest_size(1456, 819, hero=True)
('normal', 'landscape hero (16:9) fits the column')

Module Attributes

SIZES

The size classes, narrowest first.

COLUMN_WIDTH

Substack's post column, in CSS pixels (measured; the research report, section 2).

INSET_WIDTH

a little over half the column, inside the Guardian's "supporting" range and Wikipedia's 400 px ceiling.

GITHUB_ATTRS

<img> attributes per class for a GitHub comment (the comment is already about the column's width, so only inset narrows anything).

SUBSTACK_ATTRS

image2 attributes per class for python-substack.

image2 attributes per class for python-substack. resizeWidth is what the editor’s own resize handle writes. large and full are the values the stylesheet’s sizing-large / sizing-fullscreen classes imply; a draft sized in the editor and read back would confirm them (the report’s open item).

penult.figures.substack_markdown(markdown, sizes=None, *, inset_width=400)[source]#

The essay with a python-substack image marker after each image whose class says so.

The marker is an HTML comment python-substack merges into the image2 node; GitHub and every Markdown viewer hide it. Front matter and the image lines are unchanged, so article’s checks apply as before.

>>> out = substack_markdown('---\ntitle: T\nimages:\n  img/a.png: inset\n---\n# T\n\n![a](img/a.png "c")\n')
>>> out.splitlines()[-1].startswith("<!-- python-substack-image:v1 ")
True
Return type:

str

penult.figures.with_sizes(markdown, sizes)[source]#

The essay text with its images: front-matter map replaced by sizes.

Only the images key changes; the other front-matter lines are kept as written.

>>> print(with_sizes('---\ntitle: T\n---\nbody\n', {"img/a.png": "inset"}))

  img/a.png: inset
